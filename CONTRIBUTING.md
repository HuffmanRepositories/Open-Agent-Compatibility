# Contributing

Thanks for helping improve compatibility across open agent ecosystems.

## Before opening a change

1. Search this repository and upstream projects for existing work.
2. Identify the authoritative specification or implementation source.
3. State exact upstream project/version (or commit) and relevant section.
4. Explain whether the proposal is a mapping, a test, a clarification, or an upstream issue.
5. Call out semantic differences, loss, security implications, and uncertainty.

## Pull requests

- Keep changes narrowly scoped and evidence-backed.
- Do not silently normalize away protocol differences.
- Add/update fixtures when a mapping claim changes.
- Include test instructions and expected outcomes.
- Avoid presenting draft or experimental findings as stable.

## Compatibility claims

Claims must be specific to a source version, direction, feature, and tested behavior. Prefer labels such as **mapped**, **partially mapped**, **unsupported**, **ambiguous**, and **not tested** over broad “compatible” claims.

## Conduct

Be respectful, constructive, and transparent about uncertainty.
